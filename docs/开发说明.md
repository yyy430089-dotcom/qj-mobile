# 开发说明

## 结构

`vendor/` 只包含青简 v0.1.4 的 core、dictionary、format、translate 四个 crate。
`bridge/` 是 C ABI 静态库；`ios/App/` 为 SwiftUI 引导应用，`ios/Keyboard/` 为 UIKit 键盘扩展。

`DataSource/` 是可检查的 TSV；构建时通过原库的 write_qj 接口生成只读二进制，手机通过 mmap 查询。
英文表仅保留基础词库中的词形，不带领域包或大型模型。词库与释义缺一时区别处理：词库失败不启动中文引擎，英文释义失败仍允许中文输入。

## 桥接与顺序

C ABI 见 bridge/include/QJMobile.h。注册表持有整数会话句柄；destroy 后旧句柄返回错误。
dispatch 接收 JSON 动作并返回 JSON 快照。返回字符串只通过 qjm_string_free 释放。

动作：input(text)、backspace、space、enter、raw、cancel、reset、toggle_language、snapshot、choose(revision,index)、annotate(revision)。
先 query 返回中文候选，再 annotate 补英文。每次查询修改 revision，过期 choose 不上屏。Swift 串行调用引擎，保留所有文本副作用，只显示最新输入的候选；输入框变化使用 documentEpoch 丢弃旧文本副作用。

输入拼音上限 64 字符，到上限时完成当前组句；最多显示 60 个候选。用户不需要等释义再选字。
学习、日志、统计、云预测全部使用空实现或关闭。没有 App Groups entitlement，也没有网络请求。

## Mac 构建

需要带 iOS 18 SDK 的 Xcode、Rust 1.99.0、Python 3 和 XcodeGen。

```sh
brew install xcodegen
rustup toolchain install 1.99.0
cargo test --workspace --locked
python3 scripts/build_ios.py
python3 scripts/simulator_smoke.py
```

首次构建若源码包还没有 Cargo.lock，先运行 cargo generate-lockfile；固定版本后后续命令均使用 --locked。
输出位于 build/：未签名 IPA、模拟器包、报告和截图。bootstrap 使用 `python3 scripts/build_ios.py --bootstrap`，不链接 Rust。

## 验证边界

Rust 测试覆盖拼音、简拼、部分选词、退格、取消、标点、过期候选、C ABI 与 mmap 加载。
模拟器检查验证主应用安装和启动，并运行 Swift 到 C ABI 的实际候选查询、部分选词、过期候选与连续输入测试；iPhone 键盘的启用、跨应用输入、内存限制与续签必须真机完成。
GitHub 工作流不上传签名凭据，不包含 Apple 账号。公开仓库源码及数据的清单、校验值见 UPSTREAM.json。
